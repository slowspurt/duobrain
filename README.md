# duobrain

둘이 일하고, 맥락은 함께.

두 사람과 각자의 AI를 위한 Git 기반 협업 키트. 각자의 작업 환경에서 실행하는 AI가 공유 지식을 읽고, 부족한 기록을 요청하고 보충해 서로에게 반복해서 설명해야 하는 일을 줄인다.

현재 상태: 기획 단계. 아래 내용은 합의한 제품 범위이며, 아직 구현된 기능이 아니다.

구현 순서와 단계별 완료 기준은 [구현 우선순위 제안](docs/implementation-roadmap.md)에 정리한다.

## 제품 원칙

- 처음부터 2인 전용으로 제공한다. 조직, 그룹, 관리자, 다단계 권한, 다인용 확장은 현재 범위에 포함하지 않는다.
- 프로젝트 저장소가 기획, 공유 위키, 협업 요청, 처리 이력의 공유 공간이다.
- 두 사람은 각자 저장소를 클론하고 자신이 사용하는 AI로 작업한다.
- 상대의 다음 작업 시작까지 응답이 지연될 수 있는 비동기 협업을 기본으로 한다.
- 같은 시간대에 작업할 때는 시작·마무리 기록과 작업 중 동기화로 상대의 작업 범위와 변경을 확인한다.
- 각자의 AI를 별도 서버에 상주시켜 대화하게 하는 구조는 요구하지 않는다.
- 자동 공유 범위와 자동 커밋·푸시 범위는 사전에 설정한다. 허용된 범위의 기록 처리는 매번 사람을 거치지 않는다.
- 기록으로 확인된 사실과 AI의 해석을 구분한다. 근거가 없으면 지어내지 않고 기록 요청으로 연결한다.
- 원본과 변경 이력을 보존한다. 위키 요약과 중요도 조정이 원본의 의미를 바꾸지 않아야 한다.

## 시작 경험

1. 두 사람이 함께 하려는 작업을 기획한다.
2. 프로젝트에 duobrain의 지침, 문서 구조, 협업 장치를 도입한다.
3. 준비된 기획서를 넣는다. 아직 정리되지 않았다면 현재 진행 상황이나 회의록 등 보유한 자료로 시작한다.
4. 두 사람이 같은 프로젝트 저장소를 각자 클론한다.
5. 최초 연결 시 자신의 참여자 정보와 자동 공유 범위를 설정한다.
6. AI에게 duobrain 시작을 요청하면 기존 기획과 계획을 점검하고, 보완 방향과 부족한 자료를 안내한다.
7. AI가 자료를 바탕으로 협업용 기획서와 두 사람의 단계별 작업 계획을 정리한다. 이미 정리된 계획이 있다면 현재 상태에 맞는지 확인하고 이어서 사용한다.
8. 대시보드에서 목표, 현재 단계, 각자의 작업 범위, 다음 행동을 확인한다. 시작 기록을 커밋·푸시하고 동시 작업 여부에 따라 작업 공간을 분리한 뒤 작업한다.
9. 하루 작업을 마무리하면 결과와 시간 기록, 병목, 인계와 피드백 요청을 정리하고 마무리 기록을 커밋·푸시한다. 이후 시작 시에는 변경 사항과 미처리 요청을 확인한다.

클론 후 최소한의 설정으로 협업할 수 있도록 설계한다. AI 도구별 연결과 예약 실행 설정은 실제 설치 과정에서 확인해야 하며, 클론 자체가 자동화를 활성화하는 것으로 간주하지 않는다.

## 기본 기능

### 첫 실행 시 협업 기획 점검

클론 후 사용자가 AI에게 시작을 요청하면, AI는 저장소의 기획서, 회의록, 작업 현황과 기존 계획부터 읽는다. 다음 항목이 충분히 정리되어 있는지 점검한다.

- 프로젝트 목표, 결과물, 포함할 범위와 제외할 범위.
- 프로젝트 목표로 이어지는 중기 목표와 현단계 목표, 각각의 완료 기준.
- 현재 진행 단계와 이미 완료한 작업.
- 두 사람 각각의 작업 범위와 함께 결정해야 할 사항.
- 단계별 작업 순서, 선행 작업, 서로 넘겨줘야 할 결과물.
- 단계별 완료 기준과 각자가 지금 할 다음 행동.

점검 결과는 “현재 확인된 내용 → 보완할 부분 → 수정 이유와 방향 → 필요한 자료” 순서로 설명한다. 단순히 기획서가 부족하다고 알리는 데 그치지 않고 구체적인 수정 방향을 제안한다.

예: “기능 목록은 있지만 담당 범위와 진행 순서가 없습니다. 현재 완료한 작업이나 최근 회의록을 붙여주면, 이를 바탕으로 두 사람의 작업 범위와 단계별 계획을 정리하겠습니다.”

누락된 정보가 기존 기록에 있으면 먼저 활용한다. 근거가 부족한 경우 현재 진행 상황 설명, 회의록, 기존 기획서 또는 작업 목록을 대화에 붙이거나 파일로 제공하도록 안내한다. 모든 자료를 요구하지 않고 부족한 항목을 채울 수 있는 자료만 요청한다. 자료 자체가 없다면 필요한 핵심 질문으로 초안을 만든다.

제공된 자료에서 목표, 결정, 담당, 진행 상황을 추출해 협업용 기획서와 단계별 계획으로 연결한다. 계획에는 단계, 목표, 각자의 작업, 의존 관계, 완료 기준, 현재 상태와 다음 행동을 담는다. 근거가 없는 담당 배정과 일정은 제안 또는 미정으로 표시하고, AI가 만든 초안을 둘의 합의로 기록하지 않는다.

두 번째 참여자가 시작할 때 이미 완료된 초기 기획을 반복하거나 덮어쓰지 않는다. 자신의 작업 범위를 확인하고 새로 제공한 자료와 기존 계획의 차이만 보완한다. 부족한 정보에 의존하지 않는 작업은 진행할 수 있도록 하고, 필요한 판단과 자료 요청은 별도로 유지한다.

### 사용자가 보는 대시보드

두 사람이 프로젝트의 현재 상태와 다음 행동을 확인하는 대시보드를 제공한다. 공유 저장소의 기획, 위키, 요청, 로그를 바탕으로 다음 내용을 보여준다.

| 영역 | 보여줄 내용 |
| --- | --- |
| 목표 | 프로젝트 전체 목표, 중기 목표, 현단계 목표와 각각의 완료 기준 및 연결 관계. 기간이 합의되지 않았다면 미정으로 표시. |
| 프로젝트 개요 | 현재 단계, 기획 보완 상태와 아직 필요한 자료. |
| 두 사람의 작업 | 각자의 현재 작업 범위, 시작·마무리 상태, 다음 행동, 겹치는 작업과 인계 사항. |
| 시간 사용 | 최근 작업 구간, 오늘과 최근 기간의 기록된 작업 시간, 작업별 시간 사용과 시간이 많이 들어간 부분. |
| 병목 | 막힌 작업, 원인, 대기 중인 상대 작업이나 결정, 언제부터 막혔는지, 영향받는 목표와 필요한 도움. |
| 단계별 계획 | 단계별 목표와 완료 기준, 선행 작업, 진행을 막는 항목. |
| 변경 브리핑 | 마지막 확인 이후의 관련 변경, 새 결정과 보충된 기록. |
| 요청함 | 피드백·정보 보충 티켓이 누적되는 영역. 보낸 요청과 받은 요청, 미처리 건수, 처리 상태, 사람의 응답이 필요한 항목. 전체 요청함으로 확장 가능. |
| 티켓 이력 | 처리된 과거 티켓을 보는 별도 탭. 요청 원문, 응답, 처리 결과와 근거, 후속 조치를 검색하고 상세로 접근 가능. |
| 공유 지식 | 기획서, 회의록, 지침, 프롬프트·하네스와 비교 기록, 결정의 확정 상태와 근거. |
| 처리 이력 | 자동 기록과 커밋·푸시 결과, 마지막 위키 정제 결과, 실패와 미해결 사항. |

요약에서 관련 원문, 요청, 커밋으로 이동할 수 있어야 한다. 마지막 동기화 시각과 기록 갱신 시각을 표시해 오래된 상태를 실시간 현황으로 오해하지 않도록 한다. 확인할 수 없는 상태는 미확인으로 보여준다.

시간 사용은 시작·종료·일시정지·재개 기록과 작업별 활동 기록을 바탕으로 표시한다. 시작과 마무리 사이의 경과 시간을 실제 집중 작업 시간으로 표현하지 않는다. 휴식, 도구 실행, 상대 응답 대기를 구분할 수 있으면 따로 표시하고, 구분할 근거가 없으면 경과 시간 또는 추정치임을 밝힌다. 종료 기록이 없으면 현재까지 전부 일한 것으로 누적하지 않고 종료 미확인으로 표시한다. 여러 작업 구간이 겹칠 때는 개인별 시간 합계에서 중복 집계를 피한다.

시간이 오래 걸린다는 사실만으로 병목이라 단정하지 않는다. 기록으로 확인한 지연 원인과 AI가 제안하는 병목 후보를 구분한다. 이 정보는 두 사람의 다음 행동과 도움 요청을 판단하는 데 사용한다.

첫 실행에서는 기획의 보완 방향과 자료 제공 안내를 보여주고, 협업 준비가 끝나면 작업 현황 중심으로 전환한다. 자료를 대화나 파일로 제공하는 흐름을 지원하며, 대시보드 자체의 업로드·편집 범위와 실행 방식은 추후 정한다. 대시보드 제공이 별도 AI 상주 서버를 필수로 만들지는 않는다.

### 요청함과 과거 티켓 탭

피드백 요청과 정보 보충 요청은 고유 식별자를 가진 티켓으로 누적한다. 대시보드 요청함에 미해결 티켓과 건수를 보여주고, 전체 요청함으로 확장하면 `진행 중`과 `처리 이력` 탭을 오갈 수 있게 한다. 간단한 알림을 확인하거나 읽었다는 이유로 티켓이 사라지지 않는다.

| 화면 | 동작 |
| --- | --- |
| 대시보드 요청함 | 지금 확인할 티켓, 상태별 미해결 건수, 요청 유형과 상대, 필요한 도움을 요약하고 전체 보기로 연결한다. |
| 진행 중 탭 | 새 요청, 확인됨, 처리 중, 사람 응답 대기, 답변 후 후속 처리 대기를 포함해 아직 해결되지 않은 티켓을 보여준다. |
| 처리 이력 탭 | 해결한 티켓과 취소·중복 등으로 종료한 티켓을 결과별로 구분해 보존한다. 제목·내용 검색과 요청 유형, 보낸 사람·받는 사람, 관련 작업, 기간, 처리 결과 필터를 제공한다. |
| 티켓 상세 | 요청 이유와 원문, 원하는 완료 조건, 관련 목표·작업·자료, 사람과 AI의 응답, 상태 변경 시각, 처리 결과, 보충된 위키·커밋, 후속 조치를 시간순으로 보여준다. |

정보 보충은 필요한 기록이 실제 공유되었는지, 직접 피드백은 사람의 응답과 필요한 후속 처리가 끝났는지에 따라 해결 여부를 판단한다. 자료가 없거나 일부만 보충된 티켓은 해결로 표시하지 않는다. 요청이 더 이상 필요하지 않아 종료할 경우 해결과 구분되는 종료 이유를 남긴다.

완료된 티켓도 동일한 식별자와 상세 링크를 유지한다. 원래 질문이 해결되지 않았음이 드러나면 이유와 함께 다시 열어 진행 중 탭에 표시하고 이전 처리 이력을 보존한다. 별개의 후속 질문은 새 티켓으로 만들되 원래 티켓을 연결한다. 이미 진행 중인 동일 요청은 기존 티켓에 맥락을 추가해 중복 생성을 줄인다.

하루 정제에서 오래된 티켓을 요약할 수 있지만 요청·응답·종료 이유·근거 링크는 유지한다. 처리 이력은 대시보드에서 계속 접근할 수 있어야 하며 Git 로그를 직접 찾아야만 볼 수 있는 구조로 만들지 않는다.

### 작업 시작과 하루 마무리 커밋

작업 시작과 하루 작업 마무리는 공유되는 명시적 기록으로 남긴다. 단순히 커밋 메시지만 남기지 않고 구조화된 작업 기록을 커밋·푸시해 상대 AI와 대시보드가 읽을 수 있게 한다. 이 공유 절차의 허용 범위는 최초 설정에 포함한다.

| 시점 | 기록할 내용 |
| --- | --- |
| 작업 시작 | 참여자, 작업 구간 식별자, 시작 시각, 현단계 목표, 작업 범위와 관련 파일·기능, 사용할 브랜치와 기준 커밋, 알려진 의존 관계. |
| 작업 중 | 범위 변경, 일시정지·재개, 병목, 공유 가능한 진행 커밋과 인계·피드백 요청. |
| 하루 마무리 | 종료 시각, 완료·미완료 작업, 결과 커밋과 검증 결과, 시간 기록, 병목, 미공유 작업 유무, 다음 행동과 상대에게 필요한 도움. |

시작·마무리 기록의 커밋에는 해당 기록만 선택해 담고, 무관한 코드 변경을 함께 커밋하지 않는다. 코드와 협업 상태를 어떻게 브랜치에 배치할지는 추후 정하되, 코드 병합 전에도 서로의 시작·마무리 기록을 발견할 수 있어야 한다. 커밋과 원격 공유 성공을 구분하며 푸시가 실패하면 공유 대기 상태로 남긴다.

하루 중 여러 번 작업하거나 자정을 넘겨 작업할 수 있으므로 작업 구간 식별자로 시작과 종료를 연결하고 날짜만으로 상태를 판단하지 않는다. 비정상 종료로 마무리 기록이 없을 때는 다음 실행에서 상태를 복구하며 종료 시각을 임의로 확정하지 않는다.

### 동시 작업과 워크트리 분리

나중에 작업을 시작하는 사람의 AI는 원격의 최신 협업 기록과 관련 브랜치를 먼저 확인한다. 종료되지 않은 상대 작업 구간, 마지막 갱신 시각, 작업 범위와 의존 관계를 바탕으로 동시 작업 여부를 판단한다. 오래된 시작 기록만 있으면 작업 중이라고 단정하지 않고 상태 미확인으로 처리한다.

동시 작업이 확인되면 나중에 시작한 AI가 자신의 작업 브랜치와 워크트리를 분리한다. 같은 파일뿐 아니라 API, 자료 형식, 공통 설정처럼 서로 영향을 주는 범위를 확인하고 상대 작업을 추적한다. 워크트리 분리는 로컬 작업 공간을 분리하는 장치이며, 이후 병합 충돌까지 없애주는 것은 아니다.

“영향 있는 범위는 먼저 내려받아 작업한다”는 요구는 다음과 같이 적용한다.

1. 기존 클론에서 상대가 푸시한 관련 브랜치·커밋을 먼저 가져온다. 저장소가 없는 환경에서는 클론한다.
2. 영향받는 변경을 별도 워크트리에서 확인하고, 자신의 작업 기반에 필요한 변경을 반영한 뒤 진행한다. 검토하지 않은 상대 변경을 현재 작업에 무조건 병합하지 않는다.
3. 상대의 변경이 아직 공유되지 않았다면 공유된 범위까지만 확인할 수 있음을 기록하고, 필요한 진행 커밋이나 인터페이스 정보를 요청한다. 독립적으로 가능한 작업은 이어간다.
4. 작업 중에도 정해진 동기화 시점에 상대의 범위 변경과 새 커밋을 확인한다. 내 작업에 영향이 있으면 계획과 의존 관계를 갱신한다.
5. 작업 마무리 전 다시 상대 변경을 확인하고, 통합 여부와 남은 충돌·검증 항목을 인계 기록에 남긴다.

둘이 거의 동시에 시작해 서로의 시작 기록을 놓치는 경우를 다루기 위해, 시작 기록을 푸시한 뒤 작업 착수 전에 상대 기록을 재확인한다. 동시 작업 감지는 동기화 시점까지 확인한 사실이며 실시간 잠금으로 취급하지 않는다. 구체적인 동기화 주기는 추후 정한다.

### 상대에게 직접 도움을 요청하는 피드백

기록 보충 요청과 별도로, 상대 사람의 의견·검토·작업 도움이 필요한 요청을 지원한다. 예: “이 기획 방향을 직접 봐줘”, “이 구현에서 막혔는데 같이 원인을 봐줘”, “네가 만든 API와 연결하는 부분을 검토해줘.”

요청에는 관련 목표·작업, 질문 또는 막힌 부분, 이미 시도한 내용, 원하는 도움의 형태, 관련 문서·브랜치·커밋, 긴급도와 필요한 시점이 있으면 이를 담는다. AI는 사용자의 도움 요청을 정리해 공유 저장소에 남기고 상대 대시보드와 AI의 시작·작업 중 동기화에서 드러나게 한다.

상대 AI는 맥락을 정리하고 답변 초안을 준비할 수 있지만, 사람에게 직접 요청한 피드백을 자신의 답변만으로 완료 처리하지 않는다. 사람의 응답과 AI의 제안을 구분해서 기록한다. 요청, 확인, 응답 대기, 사람의 응답, 반영 또는 미반영 사유를 연결하며, 응답이 왔다는 사실과 후속 작업의 완료를 구분한다. 피드백은 명시적 합의가 없는 한 자동으로 공동 지침이 되지 않는다.

### 공유 위키와 작업 방식 비교

지침, 회의록, 결정과 이유, 작업 현황, 작업 로그, 프롬프트, 하네스를 연결해 기록한다. 사람, 작업, 작업 당시의 프롬프트·하네스 버전, 진행 과정, 결과물을 함께 추적한다.

대표 질문: “상대가 B작업에 사용한 하네스와 내가 B작업에 쓴 프롬프트·작업 방식은 어떻게 달라?”

목표, 제공한 맥락, 제약, 도구, 검증 절차, 작업 순서, 사람의 개입 등을 근거와 함께 비교한다. 차이가 결과에 미친 영향은 확인된 사실과 추론을 구분한다.

### 부족한 기록 요청과 보충

내 AI가 필요한 기록이 없음을 발견하면 관련 작업, 필요한 정보, 요청 이유를 공유 저장소에 남긴다. 상대 AI는 작업 시작 시 동기화하고 요청을 확인한다. 로컬 기록에서 답을 찾을 수 있고 자동 공유 범위 안이라면 위키를 보충하고 커밋·푸시한 뒤 처리 로그를 남긴다. 내 AI는 다음 동기화에서 보충된 기록을 읽고 원래 질문을 이어서 처리한다.

처리 로그는 요청, 참고 근거, 추가한 문서, 관련 커밋, 미해결 항목을 연결한다. 사람의 설명이나 판단이 필요한 부분만 해당 참여자에게 전달한다.

### 하루 한 번 위키 정제

하루 1회, 설정된 시각에 공유된 자료를 정제한다. 최신 상태 반영, 중복·충돌 점검, 중요도 재평가, 오래된 일상 업무 기록 요약을 수행한다. 오래됐어도 유효한 합의, 결정 이유, 재사용하는 프롬프트·하네스는 중요도를 유지한다.

최신성과 중요도를 별도로 판단하고, 무엇을 왜 정제했는지 이력을 남긴다. 중요한 정보가 오래됐거나 근거가 부족하면 갱신 요청으로 연결한다. 작업 중의 기록 요청과 응답은 하루 정제 시간을 기다리지 않는다.

예약 실행은 공유 문서를 처리하는 하나의 작업이다. 실행 위치, 모델, 비용, 인증 방식은 아직 정하지 않았다. 상대 컴퓨터에만 있는 기록은 예약 작업이 읽을 수 있다고 가정하지 않는다.

## 첫 검증 시나리오

서로 다른 두 작업 환경에서 다음 흐름을 끝까지 검증한다.

1. 한 참여자가 동일 작업에 대한 두 사람의 프롬프트·하네스·작업 방식 비교를 요청한다.
2. AI가 상대 기록의 부족한 부분을 찾아 요청을 공유한다.
3. 상대가 작업을 시작하면 변경 브리핑과 미처리 요청을 확인한다.
4. 상대 AI가 허용 범위에서 로컬 근거를 찾아 위키를 보충하고 커밋·푸시·처리 로그를 남긴다.
5. 요청한 AI가 다음 동기화에서 실제 보충 여부를 확인하고 근거 있는 비교 답변을 제공한다.
6. 이후 하루 정제에서도 출처, 결정 상태, 미해결 요청이 보존된다.

작업 중 표시, 인계 카드, 결정 근거 역추적도 제품에 포함하며 각각의 사용 흐름을 별도로 검증한다.

첫 실행과 대시보드도 다음 경우를 검증한다.

- 작업 범위와 단계별 계획이 없는 프로젝트에서 AI가 보완 방향을 설명하고 현재 진행 상황 또는 회의록을 요청한다.
- 자료를 제공하면 근거 있는 협업 기획과 두 사람의 단계별 계획을 만들고, 미정 사항을 구분한다.
- 계획이 이미 갖춰진 프로젝트와 두 번째 참여자의 첫 실행에서는 기존 계획을 보존하고 필요한 차이만 보완한다.
- 대시보드에 기획 보완 상태, 두 사람의 작업, 단계별 계획, 요청과 처리 결과가 원문 근거와 함께 나타난다.
- 동기화가 지연되거나 실패하면 마지막으로 확인한 시점과 상태를 표시한다.

동시 작업과 직접 피드백은 다음 경우를 검증한다.

- 시작·하루 마무리 기록이 각각 커밋·푸시되어 상대 AI와 대시보드에 나타나고, 푸시 실패는 공유 완료로 표시되지 않는다.
- 상대 작업 도중 시작하면 나중에 시작한 AI가 별도 워크트리를 준비하고, 영향받는 원격 변경을 확인한 뒤 진행한다.
- 거의 동시 시작, 오래된 미종료 기록, 상대의 미푸시 변경을 구분해 처리한다.
- 작업 중 범위 변경과 새 커밋이 동기화 시 드러나고, 영향받는 작업과 인계 사항이 갱신된다.
- 최근 시간 사용과 병목이 근거와 함께 보이며, 미종료 구간·휴식·중복 구간으로 실제 작업 시간을 부풀리지 않는다.
- 사람에게 직접 요청한 피드백은 AI의 자동 응답만으로 종료되지 않고, 사람의 응답과 후속 조치가 연결된다.
- 피드백·정보 보충 티켓이 요청함에 누적되고 읽은 뒤에도 미해결 티켓은 남는다.
- 티켓을 해결하면 진행 중 목록에서 처리 이력 탭으로 분류되며, 검색·필터·기존 상세 링크로 요청부터 처리 근거까지 확인할 수 있다.
- 티켓을 다시 열면 과거 이력을 보존한 채 진행 중으로 돌아오며, 취소·중복 종료와 실제 해결은 구분된다.

## 참고한 오픈소스

아래는 기능 설계의 참고 자료다. 의존성 채택이나 코드 도입을 결정한 것은 아니다. 2026-09-20 공식 저장소 문서 기준으로 조사했으며 실제 실행 검증은 아직 하지 않았다.

- [ai-memory](https://github.com/akitaonrails/ai-memory): 작업 시작 브리핑, 세션 간 인계, 기록의 위키 정리.
- [Entire CLI](https://github.com/entireio/cli): 프롬프트·세션·커밋 연결과 변경 이유 역추적. 코드 줄에서 근거로 이동하는 명령은 조사 당시 실험적 기능으로 안내되어 있었다.
- [gitmem](https://github.com/dev-boz/gitmem): 근거의 강도, 지식 충돌 처리, 오래된 정보 정제. 조사 당시 알파 단계이며 원격 관리 기능 일부는 실험적이었다.

## 아직 정하지 않은 구현 사항

- 최초 지원 AI 도구와 시작·종료 절차 연결 방식.
- 설치 명령, 문서 형식, 요청·상태 기록 형식.
- Git 동기화, 동시 수정 충돌, 푸시 실패와 재시도 처리.
- 자동 공유 대상과 로컬에만 둘 기록의 경계.
- 예약 정제 실행 위치와 실행 담당, 중복 실행 방지.
- 요청 중복 방지, 반복 제한, 부분 해결과 재개 규칙.
- 대시보드 실행 방식, 화면 구조, 자료 업로드·편집 지원 범위.
- 초기 기획 점검 항목의 문서 형식과 두 번째 참여자의 합의 확인 방식.
- 협업 상태를 코드 병합 없이 공유하는 브랜치 배치, 시작·종료 기록 형식과 작업 구간 복구 방식.
- 동시 작업 시 워크트리 생성·정리 규칙, 상대 변경 추적 주기와 통합 절차.
- 작업 시간 수집 단위, 휴식·대기 판별 방식, 시간대와 하루 마무리 기준.
- 직접 피드백의 알림 방식과 응답·반영 상태의 구체적인 처리 절차.

현재 작업 폴더명은 `sharbrain`이며, 합의된 제품명은 `duobrain`이다.
